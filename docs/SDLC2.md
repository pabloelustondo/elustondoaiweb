# SDLC² Application in This Repository

The Elustondo.ai website uses twelve numbered documentation folders to keep different engineering concerns explicit. This file is a repository-specific navigation note, not a complete definition of the broader SDLC² methodology.

Work should move iteratively: evidence from implementation, QA, release, or production may require changes to intent, design, architecture, or planning. Independent concerns may proceed in parallel when their inputs and responsibilities are clear.

The operating rules are:

- Put each durable artifact in the folder matching its principal concern.
- Link related artifacts instead of duplicating them.
- Keep plans, implemented behaviour, test evidence, preview validation, and production verification distinct.
- Do not treat a document or folder as proof that implementation or QA occurred.
- Update the relevant index when a durable document is added or superseded.
- Preserve historical references with an explicit status rather than silently presenting them as current.

See the [documentation index](README.md) for the current website artifacts and their locations.
