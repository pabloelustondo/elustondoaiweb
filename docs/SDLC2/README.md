# SDLC²

SDLC² documents how a change moves through domain analysis, intent, system modeling, testability, proof of concept, architecture, planning, specifications, implementation, review, operational reality, observability, and learning.

The canonical methodology is [`SDLC2.md`](SDLC2.md). The twelve numbered folders preserve the project-specific lifecycle concerns without imposing a rigid waterfall:

1. [`01-context-and-domain-analysis/`](01-context-and-domain-analysis/)
2. [`02-intent/`](02-intent/)
3. [`03-system-model-and-use-cases/`](03-system-model-and-use-cases/)
4. [`04-benchmarks-test-strategy-and-success-criteria/`](04-benchmarks-test-strategy-and-success-criteria/)
5. [`05-viable-proof-of-concept/`](05-viable-proof-of-concept/)
6. [`06-solution-design-and-architecture/`](06-solution-design-and-architecture/)
7. [`07-planning/`](07-planning/)
8. [`08-specifications-as-code/`](08-specifications-as-code/)
9. [`09-build-and-test/`](09-build-and-test/)
10. [`10-review-and-release/`](10-review-and-release/)
11. [`11-operational-reality/`](11-operational-reality/)
12. [`12-observability-insights-and-learning/`](12-observability-insights-and-learning/)

The [`reference/`](reference/) folder preserves unique historical SDLC² source material that is not current repository governance. Current developer instructions are in [`../DeveloperGuide/`](../DeveloperGuide/), and the maintained system description is in [`../Architecture/`](../Architecture/).
